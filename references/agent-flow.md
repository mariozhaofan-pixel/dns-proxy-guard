# DNS 与 WebRTC 主流程

2026-10-28 更新。以 [SKILL.md](../SKILL.md) 为执行入口；下图明确中国软件修复是条件分支。

```mermaid
flowchart TD
  A[开场引导：关闭 Clash 系统代理\n开启 TUN，内核与节点继续运行] --> B[核实状态并备份\n确定用户实际浏览器和配置]
  B --> C[运行 ip.net.coffee/claude/\n等待 DNS 与 WebRTC 检测完成]
  C --> D{页面和两项检测完整吗}
  D -->|否| E[查页面资源与共享链路\n错误或超时不算通过]
  E --> C
  D -->|是| F{DNS 无泄露且\nWebRTC 已禁用或无泄露}
  F -->|否| G[只修未通过项\nDNS 路径或当前浏览器 WebRTC]
  G --> H{中国软件或国内网页\n出现联网不稳定吗}
  F -->|是| H
  H -->|是| I[进入兼容路由修复\n最小改动并验证原失败业务]
  I --> C
  H -->|否且隐私项仍未过| C
  H -->|否且两项已过| J{本轮有配置改动吗}
  J -->|否| N[交付实际状态、范围和回滚\n未测场景明确标记]
  J -->|是| P[只持久化实际改动层\n代理配置才查生成链，浏览器查有效设置]
  P --> K[在同一目标浏览器重新检测两项]
  K --> L{两项通过且\n已触发的兼容故障恢复}
  L -->|否| M[定位配置回退或剩余故障\n保留有效改动再复测]
  M --> C
  L -->|是| N
```

- 关闭的是系统代理开关，不是 Clash 内核或节点；TUN 与规则/全局模式不同。
- 以目标浏览器的本轮两项结果验收，不能用内置浏览器替代，也不以信任评分验收。
- 正常的中国软件不改路由；条件分支完成后必须回主目标复测。
- 首次通过且无改动就直接交付；仅改浏览器时不重载无关的代理配置。
- 超时、错误或仅空结果不是无泄露；不拦截检测脚本/地址来刷绿灯。
- 国内加密直连例外不等于全部 DNS 经代理；页面结果不覆盖所有应用。
- 反复失败时补充证据并说明缺口，不盲目扩大 TUN、IPv6 或 UDP 改动。用户更具体的约束优先。

`assets/agent-flow.png` 是旧版通用 DNS 六步图，保留作历史素材，**不再作为当前流程入口**。当前流程与验收以本文件和 [目标页验收](acceptance.md) 为准。
