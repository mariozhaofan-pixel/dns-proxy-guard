# Agent 流程图的精确文字版

对应 [流程图](../assets/agent-flow.png)。下面的 Mermaid 是可维护的流程源；图像文字与源文发生差异时，以 SKILL.md 和本文件为准。

```mermaid
flowchart TD
  A[读取 SKILL.md\n明确系统、版本、应用和 TUN 约束] --> B{DNS 隐私目标}
  B -->|严格代理| C[查询经指定代理出口\n记录 bootstrap 例外]
  B -->|加密分流| D[国内加密解析 + 海外代理解析\n不能称全部 DNS 经代理]
  C --> E[备份并取证\nDNS 结果、实际出站、真实业务]
  D --> E
  E --> F{最早失败在哪一层}
  F -->|解析| G[解析器路径、策略优先级\n浏览器及应用内 DNS]
  F -->|连接| H[TCP/TLS 错误\n物理 IPv6 地址与默认出口]
  F -->|接口可达但业务失败| I[认证回调、回环、应用日志\n不把握手成功当业务成功]
  G --> J[限定域名、进程、目的地址和端口\n保留无关配置及回滚]
  H --> J
  I --> J
  J --> K[配置校验 + 一次改变一个因素]
  K --> L{DNS 路径符合目标\n且用户确认真实业务成功}
  L -->|否| M[撤销无效实验\n保留已有效修复，补充证据]
  M --> F
  L -->|是| N[持久化同一组有效变更\n核对幂等性、重启或订阅更新]
  N --> O[交付结果、覆盖范围、限制与回滚位置]
```

## 关键判断

- TUN 接管与远端代理出站是两件事，读取实际命中规则和出站链。
- 加密 DNS 不等于经代理，不等于匿名。明文 53 检查不能覆盖 DoH。
- 没有可用原生 IPv6 出口时，DNS 配置不会创造出口。
- 字面 IPv6 无法仅靠 `ip-version: ipv4` 变成 IPv4。需先恢复真实域名，且协议可能无法嗅探。
- 嗅探按目标 IP/端口作用，进程规则仅限定路由；两者范围不同。
- 先验证真实登录/上传，再持久化；并发修改多个因素会让归因失真。
- 固定 IP 例外会老化。不要把一次成功当作所有网络、所有应用的通用保证。
