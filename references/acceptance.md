# Net.Coffee Claude 页验收

目标页：[https://ip.net.coffee/claude/](https://ip.net.coffee/claude/)。2026-10-28 核对页面有独立的“DNS 泄露检测”和“WebRTC UDP 泄露检测”区域。本文件定义运行本 skill 时的验收方法，不表示当前机器已经完成检测。

## 前提与目标浏览器

先按 SKILL.md 引导关闭 Clash **系统代理**、开启 **TUN**，内核和可用节点继续运行。TUN 开关不等于已接管所有协议；还要核对实际出口与当前配置。规则/全局模式是另一个设置，不随本流程擅自切换。

记录用户要修复的浏览器、版本及配置/窗口类型。普通窗口、无痕窗口、其他用户配置、另一个浏览器和 agent 内置浏览器可能使用不同扩展、策略及 WebRTC 行为，结果不能互相替代。用户指定只读或不得调整 TUN 时，保留约束，说明与默认前提的差异，不擅自切换。

## 读取两个独立状态

等待当前轮次的异步检测完成，从可见页面/DOM 状态读取，不仅看截图中某个绿色标记。定位按页面标签，布局和措辞变化时重新核对，不硬编码旧元素编号。

| 项目 | 通过证据 | 不足以通过的情况 |
| --- | --- | --- |
| DNS | 完成检测并明确显示“未检测到泄露”或同义状态，结合解析器/出站证据未发现违背约定的路径 | 页面加载中、超时、服务错误、没有结果、仅 `/dns/` 页通过、只看到 DoH URL |
| WebRTC | 完成检测并显示“已禁用或无泄露”或同义状态；确实禁用、无泄露的具体含义按浏览器设置和候选出站解释 | 仅空列表、权限/脚本/网络错误、STUN 不可达被误当禁用、只关闭摄像头权限 |

若页面把“没有候选”概括成“已禁用或无泄露”，记录页面原状态，同时查看检测是否完整、有无错误及设置/出站旁证。无法区分禁用与探测失败时标记需要进一步验证，不声称 WebRTC API 已彻底禁用。不要反复重跑直到偶然出现一次绿灯就结束。

“中国出口 IPv4”卡片、Claude 信任评分、VPN 标签、住宅属性、时区和 Claude 站点可用性不是本 skill 的最终目标。中国出口卡片出现本地 IP 不等于 DNS 或 WebRTC 一定泄露；同样，高分也不能替代两项结果。不得为刷分修改时区、浏览器指纹或节点画像。

## 定位失败，而不是规避检测

- DNS 异常时可使用页面的 DNS 深度查询入口补充解析器证据；最终仍返回目标页复测两项。不要只把探测域名路由到代理来换取通过。
- WebRTC 异常时使用其深度查询和 [WebRTC 排查](webrtc.md) 关联 ICE 候选与实际出站。正常的浏览器级隐私限制可以减少候选，但不能只拦该测试的 STUN 地址或脚本制造空结果。
- 页面打不开或服务暂时失败时，先查连接链路并记录“未完成”；其他工具只能辅助定位，不能替代目标页验收。
- 已有国内加密直连 DNS 例外要列明范围。网站结果通过不代表这些查询也经代理，更不代表其他应用内置解析或系统 IPv6 全部受保护。

## 何时进入国内兼容分支

只有报告/观察到中国软件或国内网页不稳定才进入应用路由修复；正常就跳过，不预置历史微信/剪映规则。兼容改动后既要验证原失败动作，又要返回本页复测两项。不能以修好应用为由默默降低 DNS/WebRTC 目标。

## 保存后再验收

无改动且本轮两项已通过时直接交付，不要求重载。发生改动时只保存对应层：浏览器设置核对实际值，代理配置记录 profile 和持久化来源，再在目标浏览器产生新的结果。保留一份私有截图或脱敏摘要，包含日期、浏览器/配置、两项原状态、是否有检测错误，以及需要说明的直连例外。截图里的真实 IP 与账号信息不要随 skill 或公开 issue 上传。

最小交付示例只描述证据，不预填成功：

```text
目标浏览器/配置：本次实际使用的浏览器及配置
检测时间：本轮时间
DNS：页面状态；必要的解析器和出站结论
WebRTC：页面状态；禁用或无泄露的旁证/仍不确定之处
国内兼容分支：未触发 / 原故障及用户确认结果
持久化：实际写入与加载方式；未测的重启/更新场景
范围与回滚：直连例外及私有备份位置
```
