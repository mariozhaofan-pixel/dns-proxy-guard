# Mihomo 配置落地方法

这些是根据目标构造候选配置的步骤，不是可整段覆盖的默认配置。字段依据为 Mihomo v1.19.32；始终核对当前版本和运行态。[官方 DNS 配置](https://wiki.metacubex.one/config/dns/)

只有中国软件/国内网页联网不稳定时，才读取 [已验证规则配方](verified-rule-recipe.md) 中的具体进程规则、十四项 DNS 例外与移植条件；这些不是主流程默认值。主流程修 DNS 之后仍要完成 [DNS/WebRTC 双项验收](acceptance.md)。

## 1. 先把解析器与出口配对

对于每条 `nameserver`、`fallback`、`nameserver-policy`、`direct-nameserver`，记录“解析器身份 / 传输 / 出站 / 是否属于例外”。节点的 `proxy-server-nameserver` 和解析器的 `default-nameserver` 单列，避免启动循环依赖。

- **严格代理目标**：选择用户允许的解析器，并将这些查询显式路由到已存在、已验证的代理或代理组。DIRECT 业务的 DNS 也不能遗留在未经允许的直连解析器上。检查所有旧的域名策略、fallback 和浏览器/应用 DoH，而不只是修改 `nameserver`。
- **加密分流目标**：仅对明确允许直连解析的域名配置国内加密解析器；海外 DNS 经代理。业务选择 DIRECT 与 DNS 选择 DIRECT 是两条独立策略。报告时注明直连解析器能看到本地出口。

官方支持的上游形式可以包含代理选择及选项后缀，例如 `https://dns.example/dns-query#PROXY`。其中 `dns.example` 和 `PROXY` 仅是说明格式的符号，**不得直接应用**：必须替换为用户允许、TLS 校验正常的真实解析器 URI 和实际存在的出站名。检查选中节点及失败回退，不能让一个含 DIRECT 的选择组静默回退到直连。

若代理节点域名必须先直连解析，严格零例外目标可能无法在现有结构下启动。说明依赖并让用户选择可接受的引导方式，不隐瞒例外、不关闭 TLS 校验。解析器主机是 IP 时也要验证证书与协议支持，不能把任意 DNS IP 拼成 DoH URL。

## 2. 针对应用构造域名策略

只有出现 CDN 调度、fake-ip 兼容或 IPv6 回退证据时，才添加局部例外。

1. 从目标进程连接日志确定主机，不根据产品名称猜测整个域名集团。
2. 为这些主机使用符合用户目标的解析器路径。v1.19.32 支持上游参数 `disable-ipv6=true` 抑制 AAAA；若没有 IPv6 故障证据，不默认使用它。[实现](https://github.com/MetaCubeX/mihomo/blob/v1.19.32/dns/util.go)
3. 具体域名策略放在可能提前匹配的宽泛策略之前，并用真实查询验证顺序；保留其他已有策略。
4. 若 DIRECT 连接使用独立 `direct-nameserver`，决定是否让其继承策略；需要继承时核实 `direct-nameserver-follow-policy: true` 生效。它不是“全应用关闭 IPv6”。
5. 若需要真实 IP 例外，先检查 `fake-ip-filter-mode` 的含义。黑名单模式与白名单模式不能使用同一种追加逻辑。DNS 返回 A/AAAA、应用实际拿到的地址和出站重新解析要分别检查。
6. 对内置 HTTPDNS/DoH、缓存及固定 IP 请求单独定位。普通 DNS 策略无法保证覆盖它们；应用选项须按版本备份和验证，不批量改所有软件的设置。

## 3. 构造连接分流

使用实际进程名/路径、域名和规则命中日志，明确哪一条规则优先。

- 让目标国内软件 DIRECT，仍可保留 TUN 接管；它不等于软件经境外节点。
- 用域名或地域规则时检查误伤范围与已有顺序；不可为了一个上传端点将整个协议或大网段全局放行/拒绝。
- 必须针对字面 IPv6 做兼容性修复时，使用 [离线生成器](helper-tools.md)，审查目的 IP/端口的嗅探影响，以及进程出站的影响。原有 sniffer 或脚本逻辑冲突需合并，不强行覆盖。
- 代理环境变量仅对读取它的进程生效。修改 `NO_PROXY` 时保留旧值、按该软件支持的匹配语法添加；正常重启后再检查继承值。它不是替代所有内核规则的总开关。

## 4. 校验、应用与持久化

候选配置保存在本机私有目录。先做语义比较，再用实际内核的配置检查模式验证；根据本机 `--help` 确认参数，不假定二进制路径。

```sh
mihomo -t -d /private/path/config-home -f /private/path/candidate.yaml
```

采用该客户端支持的加载方式。控制器只能通过既有受保护的本地接口访问，不为方便诊断开启无鉴权的公网监听。凭据放在请求头或受保护的客户端存储中，不出现在 URL、命令输出、截图或仓库。

Mihomo 的配置 API 可加载配置；服务进程对文件路径可能另有访问限制，应核对当前 API 与安全路径，而不是到处复制含节点秘密的文件。v1.19.32 支持配置文本 `payload`；此调用不会运行 GUI 的扩展脚本。[配置 API](https://wiki.metacubex.one/api/)、[配置接口实现](https://github.com/MetaCubeX/mihomo/blob/v1.19.32/hub/route/configs.go)

应用后验证目标页 DNS/WebRTC 与实际出站；触发国内兼容分支时另验原失败业务。成功后才将相同变更写入持久化来源，保留全部订阅节点和无关配置。客户端重新生成、更新订阅与运行态热加载是不同事件；交付中写清真正测试过哪些。

修复后复发、需要全局扩展或遇到配置回退时，继续读 [持久化与配置漂移](persistence.md)，检查实际 UID、生成顺序、客户端 DNS 字段覆盖及脚本异常处理。不要重复改生成文件来代替修正来源。
